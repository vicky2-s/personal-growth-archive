# 01 · 项目架构设计

## 1. 项目定位

**人生档案馆 (Personal Growth Archive)**

- 个人数字档案 + 项目管理 + 成长记录 + 能力地图 + 人生时间轴
- 核心理念：**文件是经历的证据，项目是经历的节点，能力由真实行为证据积累**。

## 2. 技术选型

| 层 | 方案 | 说明 |
|---|---|---|
| 前端 | HTML + CSS + 原生 JS | 无框架依赖，模块化拆分 |
| 后端 / 数据库 | Supabase (PostgreSQL) | 认证 + 数据库 + Storage + RLS |
| 部署 | GitHub Pages | 纯静态托管 |
| AI（预留） | 接口层抽象 | MVP 用模拟数据，不阻塞运行 |

## 3. 目录结构


### 结构原则

1. **单 HTML + 多 JS 模块**：用 hash 路由实现多"页面"，避免每个页面一个 HTML 导致重复加载。
2. **分层清晰**：`supabase.js`（底层）→ `store.js`（数据层）→ `pages/*`（视图层）→ `ui.js`（通用组件）。
3. **能力框架常量**集中在 `config.js`，六大领域与 30 项能力可配置。
4. **Demo 数据独立**在 `seed.js`，且明确标注，未来一键关闭。

## 4. 认证模型

- 使用 Supabase Auth 的邮箱密码登录（可选：GitHub OAuth 未来接入）。
- 注册后通过触发器自动在 `public.users` 建行。
- 所有数据表启用 RLS，用户只能访问自己的数据。

## 5. 数据分层说明

| 数据 | 是否 Demo | 说明 |
|---|---|---|
| 技能库 `skills` | 种子数据（真） | 六大领域 30 项能力，全局共享 |
| 成就定义 `achievements` | 种子数据（真） | 10 个成就定义 |
| 用户项目/文件/证据 | 真实 Supabase 数据 | 用户自己录入 |
| `seed.js` 中的演示数据 | Demo | 未登录/演示模式下展示，标注"演示" |

## 6. 扩展性设计

- 新增能力：向 `skills` 表插入即可，UI 自动适配。
- 新增成就：向 `achievements` 表插入定义，前端展示自动适配。
- 接入真实 AI：实现 `store.js` 中的 `ai.analyze()` 接口，返回结构已预留（见 `ai_analysis` 表）。
- 新增页面：在 `router.js` 注册路由 + 新增 `pages/*.js`。
