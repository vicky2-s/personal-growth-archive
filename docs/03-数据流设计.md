# 03 · 数据流设计

## 1. 能力证据驱动的核心数据流

```
用户完成真实项目 (projects)
        ↓
项目产生真实贡献 (contributions)
        ↓
贡献关联具体能力 (skill_evidence: contribution_id + skill_id)
        ↓
形成能力证据 (含来源/时间/行为)
        ↓
证据持续积累 → 计算能力等级 (skill_level 函数)
```

> 关键规则：能力等级 = 有效证据数量映射，**不是 AI 主观评分**。
> 同一项目中同一能力只计 1 条有效证据（`skill_level` 函数内 `distinct project_id`）。

## 2. 各模块数据流

### 文件上传
```
用户选文件 → supabase.storage.upload('files/{user_id}/{uuid}.{ext}')
  → 得到存储路径
  → 写入 files 表（file_url = 路径，project_id 可为 null）
  → 归入「未分类」，或选择/新建项目
```

### 生成能力证据（手动）
```
项目详情 → 添加贡献 → 「关联能力」→ 选择 skill_id + 行为描述 + 时间
  → 写入 skill_evidence (confirmed=true)
  → 能力地图/首页计数自动更新
```

### 生成能力证据（AI，预留）
```
上传文件 → ai.analyze(file)（MVP 返回模拟结构）
  → 写入 ai_analysis (status=pending)
  → 前端展示 AI 推荐能力清单
  → 用户勾选确认 → 写入 skill_evidence (ai_suggested=true, confirmed=true)
  → ai_analysis.status = confirmed
```

### 项目归档
```
项目 status 改为「已完成」→ 自动进入档案/时间轴
  → 文件不删除（files 与 projects 仅关联，不级联删除）
```

### 搜索
```
关键词 → 并行查询：
  projects (name/description/tags)
  files (file_name/description/tags)
  skill_evidence (source/evidence_description)
  → 合并展示（MVP 用 ILIKE，未来可升级全文检索）
```

## 3. 前端数据访问封装（store.js）

统一封装，页面层不直接调用 supabase：

```js
// 概念示意
Store.projects.list({ status, type, q })
Store.projects.get(id)
Store.projects.create(data)
Store.files.upload(file, projectId)
Store.files.list({ year, project, type, tag, q })
Store.skills.getMap()                 // 六大领域 + 证据数
Store.skills.evidence.add(...)
Store.evidence.list(skillId)          // 按年份分组
Store.timeline.list({ year, type, skill })
Store.achievements.list()             // 含 unlocked 状态
Store.ai.analyze(fileId)              // 预留接口
```

## 4. 能力等级计算（证据 → Level）

| 有效证据数 | Level | 标签 |
|---|---|---|
| 0 | 0 | 暂无证据 |
| 1-2 | 1 | 初步尝试 |
| 3-5 | 2 | 持续实践 |
| 6-10 | 3 | 熟练实践 |
| 11-20 | 4 | 深度积累 |
| 21+ | 5 | 长期专业积累 |

该逻辑在数据库（`skill_level` 函数）与前端（`config.js` 兜底）各实现一次，保持一致。

## 5. 状态同步

- 采用「写后重新拉取」的简单策略，避免复杂缓存。
- 页面切换时按需加载，减少请求。
- 数据变更后，首页统计、能力地图、时间轴在下次进入时刷新。
